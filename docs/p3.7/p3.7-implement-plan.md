# P3.7 实施方案——蒸馏注入消费端上下文（TreeWalker agent 能力模型）

> 状态：计划中（待实施）。
> 关联：ROADMAP.md `P3.7` 章节、issue 待建。
> 前置调研：distiller prompt 现状 + TreeWalker agent 动作词汇/能力边界双向探索（见本文「调研依据」）。

## 一、背景与动机

TreeForge 蒸馏的 skill 是 TreeWalker 专用、不需通用。理论上，让蒸馏 LLM 知道消费端（TreeWalker agent）的能力边界，应该能产出更对口的 skill。本方案把这个直觉落成具体的 prompt 改动。

### 现状问题（调研实证）

对 `harness/distiller.py` 的 prompt 模板做穷举检查，发现消费端模型严重缺失：

| 维度 | 现状 | 问题 |
|---|---|---|
| 消费端**感知**模型 | ✅ 有：「The consumer is an LLM agent that reads DOM as `[index]<tag attr=val /> text`.」 | 够用——selectors.md 已经能引用对的属性格式 |
| 消费端**能力**模型（动作词汇） | ❌ 无：整个 prompt 里 "tool" 出现 **0 次**，action vocabulary 一次没列 | sop 动词只能用泛泛英文（「点击上传按钮」），落不到真实 tool 名（`upload_file(index, path)`） |
| 唯一动作名 | `upload_file` 埋在一个 quirks **示例**里 | LLM 碰巧命中示例才知道这个动作；其它动作（`select_dropdown` / `send_keys`…）完全不知道 |

### 实证危害（A/B 测数据）

- 蒸馏版 skill **漏了「upload_file 直注」这条最值钱的 quirk**，比手写版小 38%（`docs/skill/distilled-skill-quality-2026-07-28.md:31`）。
- 手写的高质量 skill（`member.bilibili.com/`、`creator.douyin.com/`）**全都直接引用真实动作名**：`upload_file(index=…, path=…)`、`select_dropdown(index=…, value=…)`。
- B 站封面 baseline 33% vs treatment 100%（`docs/skill/bilibili-ab-test-2026-07-28.md:72`），baseline 就栽在隐藏 file input 这个坑上。

### 核心洞察：「别写」比「能做」更值钱

探索 TreeWalker agent 时发现一个关键事实——它有**很多能力是 session 层自动处理的，不需要 skill 教**：

| Agent 自动处理（session 层） | 代码位置 | 如果 skill 教了会怎样 |
|---|---|---|
| JS 点击 / 元素遮挡自动兜底（`_js_click_fallback`） | `browser/session.py:2248-2299` | 浪费 token；`docs/tools-optimize/click.md:34` 明确「不要把 force/js_fallback 暴露给 LLM」 |
| 下拉点击自动降级（点 dropdown 形元素自动读 options） | G9 dropdown-degradation，`actions.py:602+` | 误导（LLM 可能写「先点下拉再选项」，但 agent 点一下就够） |
| 多 file input 已带 `class`/`accept` + `[File Inputs]` 段 | dom-snapshot 序列化（issue #96 修复） | 重复（LLM 抄 DOM 已展示的信息） |
| `index === backend_node_id`，无运行时模糊匹配 | `actions.py:448-463` `_get_element_by_index` | 误解（LLM 可能以为有 xpath 兜底） |

**所以蒸馏 prompt 需要的不只是「agent 能做什么」，更是「agent 已经自动做什么 → 你不用写」**。这正好和 distill prompt 现有的决策启发式（「If the agent reads the DOM text, can it figure this out itself? If yes, do NOT write it.」）一脉相承，但那条启发式目前只覆盖了「DOM 能看出来的」，没覆盖「agent 自动处理的」。

## 二、改动范围（纯 prompt 改动，无新依赖）

### 不动的边界

- ❌ TreeForge 运行时不依赖 TreeWalker（两项目独立发布，版本不同步）
- ❌ 搬 TreeWalker DOM 序列化 / 匹配逻辑过来（replay 的事，P3.6 已确认不搬）
- ❌ 改 TreeWalker 那一端任何东西（skill 注入逻辑不动）
- ❌ 期望模板模式（`--no-llm`）受益——无 LLM，注入再多也没用；此改进主要服务真 LLM 蒸馏

### 改的文件（预估 2 个 + 测试）

- `harness/distiller.py`：加 `_CONSUMER_CONTEXT` 常量 + 注入 `_DISTILL_PROMPT_TEMPLATE` + 调整 quirks WRITE/Do-NOT-WRITE 规则
- `tests/test_distiller.py`：加测试钉住 prompt 含消费端上下文段

## 三、实施步骤

### S1：新增 `_CONSUMER_CONTEXT` 常量（distiller.py）

新增一个模块级常量，内容是 TreeWalker agent 的能力模型。**镜像自 TreeWalker `src/tree_walker/tools/models.py` 的 `ACTION_DEFINITIONS`（24 个动作）+ `browser/session.py` 的自动兜底逻辑**，但只挑蒸馏相关的精简版。

文件头注释标明镜像来源 + 需手动同步：

```python
# 镜像自 TreeWalker src/tree_walker/tools/models.py ACTION_DEFINITIONS（24 动作）
# + browser/session.py 自动兜底逻辑。TreeWalker 动作集稳定（变化慢），维护一份 prompt
# 片段成本可控。改 TreeWalker 动作集时需手动同步此处——加测试钉住关键动作名。
_CONSUMER_CONTEXT = """\
# Consumer context — the agent that will use this skill

The consumer is **TreeWalker agent**. It drives the browser via a fixed set of actions.
Reference actions by their EXACT names in sop/quirks when describing method requirements.

## Action vocabulary (distill-relevant subset)

- `click(index)` — click element by index (index === backend_node_id, from the DOM tree).
- `input_text(index, text, clear=true)` — type into input/textarea/contenteditable.
- `select_dropdown(index, value)` — pick an option from a <select> by value.
- `upload_file(index, path)` — inject a file into an <input type=file>. **MUST use this for
  hidden file inputs**; clicking a file input opens an OS dialog the agent CANNOT drive.
- `send_keys(keys)` — key combos / named keys (e.g. "Control+a", "Enter", "Escape", "F5").
- `scroll(amount, direction)` — scroll the page (amount 1-10).
- `navigate(url, new_tab=false)` / `go_back()` — navigation.
- `wait(seconds)` — explicit wait (use for async render after an action).
- `done(text, success)` — mark task complete.

## What the agent ALREADY handles automatically — DO NOT write these into the skill

- **JS click / occlusion**: if an element is covered by an overlay, the agent auto-falls-back
  to JS click. Do NOT write "use JS click" / "element is occluded".
- **Dropdown click degradation**: clicking a dropdown-shaped element auto-reads its options.
  Do NOT write "click the dropdown first, then select" — one click suffices.
- **Multi file-input disambiguation**: the DOM already lists each <input type=file> with its
  `class`, `accept`, visible/hidden status in a `[File Inputs]` section. Do NOT copy this
  verbatim — only note it when the disambiguation is NON-obvious (e.g. conditional rendering).
- **index resolution**: `index` is the backend node id shown in the DOM tree; the agent looks
  it up directly. There is NO xpath/attribute fuzzy matching at runtime, so skills must guide
  attribute-based identification for ambiguous elements (that's what selectors.md is for).
"""
```

### S2：注入 prompt + 调整 quirks 规则（distiller.py）

1. 在 `_DISTILL_PROMPT_TEMPLATE` 里，紧跟现有「The consumer is an LLM agent that reads DOM...」那句之后，插入 `{consumer_context}` 占位符（值 = `_CONSUMER_CONTEXT`）。
2. quirks **WRITE** 规则里的「Action-method requirements」从孤立示例提升为有动作词汇支撑的规则——现有示例 `upload_file(index, path)` 保留，但现在 LLM 知道这是 9 个动作之一，不是孤例。
3. quirks **Do-NOT-WRITE** 规则加一条：「agent 自动处理的（JS 点击 / 遮挡 / 下拉降级 / 多 file input 已带 class·accept）——session 层已兜底，写进 skill 是噪声」。
4. 现有决策启发式「If the agent reads the DOM text, can it figure this out itself? If yes, do NOT write it.」扩成两条：
   - 「If the agent reads the DOM text, can it figure this out itself? If yes, do NOT write it.」（原有，DOM 可见）
   - 「If the agent's session layer already handles it automatically (JS click / occlusion / dropdown / file-input metadata), do NOT write it.」（新增，自动兜底）

## 六、调研依据（事实出处）

### TreeForge distill prompt 现状（harness/distiller.py）

- 系统 prompt `_DISTILL_SYSTEM`（47-51 行）：3 句，只说 "for browser automation"，无 agent 名。
- 用户消息 `_DISTILL_PROMPT_TEMPLATE`（53-177 行）：消费端描述仅一句（104 行）"The consumer is an LLM agent that reads DOM as `[index]<tag attr=val /> text`."——**感知**模型，无能力模型。
- "tool" 出现 0 次；唯一动作名 `upload_file` 在 quirks 示例（138-139 行）。
- TreeWalker 仅出现 1 次（77-78 行），作为 DOM 快照**来源**标注，非消费端描述。

### TreeWalker agent 能力（消费端事实）

- 动作词汇权威定义：`src/tree_walker/tools/models.py` `ACTION_DEFINITIONS`（538-667 行，24 动作）。
- DOM 格式：`[index]<tag attr=val /> text`，来自 dom-snapshot 序列化器；`index === backend_node_id`。
- skill 注入：`src/tree_walker/skills/loader.py` `load_for_host(host)`，**原文本注入**（不解析），读 `domain-skills/<host>/_sop.md` + `selectors.md` + `quirks.md`，拼到 `[Domain Skill]` 段（state message 里，在 `[Task]` 后 `[Available Secrets]` 前）。
- 自动兜底：`browser/session.py:2248-2299`（`_is_element_occluded` + `_js_click_fallback`）；`docs/tools-optimize/click.md:34` 明确不暴露给 LLM。
- 运行时无模糊匹配：`actions.py:448-463` `_get_element_by_index` 直接 `selector_map[index]` → CDP；index 失效就重 `get_state`，无 xpath/attribute 兜底（replay 侧的 7 级匹配是另一套，`rerun.py:847`，distill 不参与）。
- 已知高价值 quirks（手写 skill 实证）：隐藏 file input 必须直注、SPA 无 URL 切换、上传后强等待、tag 输入要按 Enter、多 file input 按 accept 区分。
